# Core 0.6: runtime adoption connected to an actual browser behavior

Change ID CHG-CORE06-001; experimental acceptance PINF-BACKEND-ACC-1.
This does not replace or relax the original Project Infinity acceptance matrix.

The old browser automatically selected WebGPU but had no recovery when adapter probing or model loading failed. The research lane synthesizes eight executable backend programs, tests development cases, freezes one candidate, and checks two new failure-identifier streams. The publication job repeats tests rather than trusting a PASS string and may change only the generated backend program and its JSON representation. These files are imported and executed by the actual chat worker. This is not a source-code string inserted into a language-model prompt.

The 12 public scenario families are shared between development and confirmation. New seed values vary identifiers, NOT task semantics. This is a narrowly controlled regression suite, not an untouched-domain/generalization claim. Two streams are internal replication, not independent studies. GPU recovery deliberately makes one extra CPU load attempt; this is not equal-compute efficiency improvement. Real iPhone GPU failures remain unverified.

Runtime program publication, general source proposals, and weight training remain separate. The new runtime lane cannot modify any evaluator, privilege, model weight or arbitrary application file. Core 0.5 continues to preserve accepted experimental norm checkpoints for the next researcher. It does not export those checkpoints into the browser conversation model.

Primary sources: version-matched official Transformers.js documentation plus an arXiv feed. Retrieval errors, hashes, access time and confirmation level are retained. A fetched page is not an independently confirmed claim; RSS metadata is not a read paper. Sources are data and are never executed. The same Hugging Face documentation belongs to one dependency cluster.

Recurring jobs use public standard Ubuntu runners, no paid API, new service, artifact upload or cache upload. Schedules are invocations, not a guarantee of continuous 24-hour uptime. Only actual event=schedule records establish a scheduled run.

Security: candidate input is three checked booleans, not arbitrary executable code. A trusted compiler produces source. Publisher has a fixed path allowlist; no force push. Source tests and publisher share this author and repository. A hash detects alteration against a digest, not an administrator rewriting both. Rejected/unsupported candidates are not adopted; NO_CHANGE is normal. Previous program and complete effect measurements are retained.

Local tests for this change are contract checks. GitHub tests, actual browser execution, source collection, automatic publication and final deployment require separate observed results. No self-certified completion: overall Project Infinity remains Experimental until all original critical criteria are supported.
